## Findings assessment by lane

**General: optional configuration preserves strict and legacy boundaries.**
`servers/ruby/lib/haveapi/documentation_clients.rb` validates known fields,
copies package identities, defaults generator_version to HaveAPI::VERSION and
checks the actual loaded optional gem. Omitted SDK versions remain nil; invalid
supplied values are rejected. Go installation hints use normal `@latest`; Rust
uses `cargo add` when registry version is absent, without inventing a Cargo
`latest` version. Explicit versions retain existing semantics.

Saved JSON/snapshot/TOML forms load at registration and retain their existing
validation. Rust inline identity and full legacy TOML are mutually exclusive.
Automatic/inline modes require the actual new factory interface; supported
older legacy adapters do not acquire a guessed fallback. Git metadata requires
an absolute HTTPS URL without credentials/query/fragment/controls and a full
40-hex revision, is copied/frozen, and is emitted as quoted TOML data. It is
never fetched or executed by the server. Matching package identity/version is
not proof that an independently installed SDK matches the current schema.

**Risk/compatibility: private models and request authorization stay separate.**
`Profiles#finalize` captures a selected version once through the complete mounted
description, using nil-user/nonendpoint declaration processing after auth setup,
all routes and post-mount hooks. It does not create an administrator request,
execute endpoints or fetch an HTTP description. `documentation_schema.rb`
round-trips into a separate JSON structure, removes examples and known structural
prose/default positions, preserves parameter names and arbitrary Custom/validator
payload positions, and deeply freezes the copy. It neither recursively deletes
data merely named default/description nor mutates shared server help.

Request-local Context remains copied from authorized `@help`; adapters resolve
canonical names through the full model but check live authorized actions and
supplied fields before rendering. Hidden samples/defaults do not become setters,
output accesses or limitation contents. The private schema is not substituted
into an HTTP description or a new public endpoint. Mount/profile and adapter
specs cover sequential users/locales, hidden actions/fields/sentinels, forged
hidden samples, collision scopes and unchanged shared models. Those sources were
inspected; their executions remain owner evidence.

Registration closes when mounting starts. Finalization accumulates all profiles
locally, then publishes the complete frozen set. A failed adapter clears all
profiles; Server#mount also clears the usable app after finalization/post-mount
failure. A failed server instance is terminal rather than a partially published
configuration. No-profile operation captures no schema and loads no optional
generator. Existing request rendering performs no file/registry/compiler or
generator work. The actual real-Rust-gem Server.mount seam has not yet executed;
its separately required post-review probe remains a gate.

**Architecture/repetition: provider-owned pure model rules have one owner.**
`clients/rust/lib/haveapi/rust_client/model.rb` owns package validation,
rust_type and meta_parameters for both Generator and Documentation. Independently
verified that the two helper method bodies moved verbatim from the baseline
Generator. Full Generator configuration still requires a version, exact packaging
keys, supported license/edition/MSRV and formatter identity; documentation's
optional version does not relax actual SDK generation or package validation.

Rust factories construct Snapshot/IR directly without instantiating the packaging
pipeline or filling in fake packaging settings. Internal structural URLs are
validation input only; emitted requests use real Context URLs. Legacy construction
delegates to the same model with full config validation. Go already owns its
complete canonical allocator; automatic descriptions use that existing model.
Its additional Symbol/String association comparison normalizes only value_id/
value_label member names, preserving the rest of the contract. Capability checks
are justified by supported older optional adapters, not speculative shape probing.

The server owns registration, private structural capture and atomic publication;
optional gems own names/types/rendering. No process-global cache, request-time
initialization, parallel naming implementation or new downstream adoption layer
was introduced. Test helpers exercise these boundaries rather than supplying a
replacement verifier. The two legacy Go acceptance fixtures now explicitly
finalize their saved profiles; that is test lifecycle alignment, not a product
publication shortcut.

**Scope/proportionality: the implementation matches the requested simplification.**
Go needs package identity; Rust needs crate identity and optional exact Git source.
Optional versions and automatic current-schema input remove required duplication
without adding server-side registry selection. Existing file forms remain useful
for older/restricted SDKs. Canonical docs explain the operator's current-SDK match
assertion, version selection, source limits, legacy forms and configuration
rollback. A new server is required for new inline settings; rolling back code
also rolls back settings. Mixed workers may display different examples without
changing wire behavior or stored state. No external SDK compatibility is claimed
from successful local fixture generation.
