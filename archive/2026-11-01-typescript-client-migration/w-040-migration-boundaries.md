## Compatibility and denial

Peer32dd4dbb and architect constraints bind new retract/delete and `expected_state` to API `8225229aa0e3306f8b1723c5583969a33c64571c` or independently equivalent live capabilities. API7 is insufficient. The running preview's API610 lacks these additions and remains unchanged.

Preserve all SIX draft-sync child mutation gates: CVE create/update/delete and nested node-status create/update/delete. A draft write sends `expected_state: 'draft'` and the frozen `expected_content_revision`; parent update/publish/retract/delete retain their own applicable guards. Generated methods provide typed operations, not this application policy. Validate action presence, integer revision parameter, string state parameter and actual allowed selected state. Preserve array or labeled-object choices, and fail closed on missing/malformed descriptions. Keep fresh authenticated root discovery; no anonymous capability cache. Retract/delete retain object-specific action description checks before writes. Capability failures, missing actions/fields and unsupported backend responses must produce zero mutations, without omitting fields or retrying an unguarded operation.

Snapshot invariants: bracket child reads with parent Show; require unchanged revision AND state; compare the rendered parent/status target with the fresh capture; increment revisions only after each successful write; reject contradictory returned revisions; freeze captured values across query refreshes. An editor/lifecycle/bulk attempt blocks resubmission after refusal or uncertain/partial outcome until an explicit fresh load. Keep abort, transport receipt/error and no automatic write replay behavior in the existing shared policy.
