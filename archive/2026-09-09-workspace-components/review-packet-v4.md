## Commit structure and bounded decisions

- Mechanical history extraction, reusable APIs, packaging, host ownership,
  portal policy, workspace capabilities, downstream selection, configuration
  adoption, and generated input updates remain separate commits where they can
  be reviewed or reverted independently.
- Tests and documentation stay with the behavior they specify. The final
  portal remediation deliberately bundles its application glue, legacy route
  aliases, browser contract, exact `codex-web` dependency update, and generated
  Nix vendor hash: the portal source cannot compile or exercise the shared
  store and compatibility-path APIs without that exact provider revision.
- The two downstream follow-ups contain only generated/exact pins to the
  remediated provider and consumer heads. The `confctl` message and changelog
  are retained exactly as generated under repository policy.
- Rejected alternatives were a separate App Server proxy service, allowing
  browser input to choose sockets/threads/directories, retaining two durable
  browser-store implementations, a lifetime-exclusive ledger owner, generic
  prompt auto-answering, and merging configuration merely to deploy. They
  either weaken authority boundaries, break independent lifecycle commands,
  create drift, or exceed the requested component boundary.
- The user authorized deployment to aitherdev. They did not authorize release,
  default-branch integration, archival, deletion, or stopping this session.

## Compatibility and deployment decisions

- The core Codex client accepts explicit identity, defaults, runtime roots,
  source kinds, developer instructions, and optional nonblocking prompt policy.
  Generic clients do not auto-answer prompts.
- The durable ledger remains schema 3 and retains the serialized
  `retirements` compatibility key. Each transaction obtains the mode-0600
  interprocess lock, reloads the latest ledger state, performs the mutation,
  and releases the lock. Independent lifecycle commands can therefore acquire
  the lock between portal requests instead of being excluded for the portal's
  entire lifetime.
- Browser send and queue mutations use the single durable-store implementation
  exported by `codex-web`, while retaining the existing portal key prefixes and
  record shapes. Writes and removals are read back before network I/O can
  proceed; missing, corrupt, or silently discarded storage fails closed.
- Collaboration mode buttons are rendered from the server catalog. No mode
  name is hard-coded into the session template; new modes can appear without a
  portal JavaScript release.
- The public reusable API is `/codex/conversations/<id>/...`. During the first
  compatibility window the portal intentionally continues to generate its old
  `/api/sessions/<slug>/...` conversation paths, and the new server aliases
  those exact routes to the shared handler. Thus an old tab survives an upgrade
  and a new tab survives rollback to the preceding server generation.
- Package switching reconciles a fixed command and skill inventory. Tombstones
  remain for every generation in the rollback window. Only links resolving
  into selected or retained package generations are removed; unrelated
  same-name symlinks remain untouched. Rollback and compensation pass the exact
  restored generation.
- `.dev-workspace.json` opts vpsFree.cz into aitherdev labels, SSH attachment,
  and both development-cluster providers. Generic workspaces expose none.
- Deploy the system substrate first. It leaves the user-owned router, portal,
  Codex, tmux, registry, session tracking, and authority state in place. Switch
  the user profile second; the preceding profile/Codex pair remains available
  through `workspace-host rollback`.
- Existing aitherdev credential, PKI, certificate, socket, hostname, listener,
  group, firewall, and public CA paths are unchanged. System Codex remains
  installed for the first rollout's rollback window.

## Prior final-review findings and remediations

- Architecture blocking: `codex-web` and the portal duplicated browser durable
  attempt storage and disagreed on write verification. Remediated by exporting
  one configurable store from `codex-web`; the portal adapters preserve only
  application-specific keys and record encoding. The portal browser contract
  imports and tests the exact served shared module.
- Architecture important: the portal hard-coded Default and Plan controls.
  Remediated by catalog-driven rendering with a regression test for a third
  mode.
- Risk blocking: the portal held the ledger lock for its entire client
  lifetime, excluding lifecycle CLI processes. Remediated with short
  per-transaction locks, reload-under-lock semantics, and a subprocess test
  that retires an attempt between a simulated response loss and recovery.
- Risk important: changing browser conversation paths broke open tabs during
  either upgrade direction. Remediated with explicit browser paths and exact
  legacy server aliases, covered by route and shipped-browser integration
  tests. Workspace-only session operations are not routed through the shared
  handler.
