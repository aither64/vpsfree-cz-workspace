## v33 findings and remediation

- The organization history now has one valid migration boundary. Private
  migration packaging, documentation and tests are folded into the migration
  commit, so the helper is private at the first commit that introduces it.
- The configuration dependency history now has a manual channel declaration
  commit followed by the exact, unedited commit generated by
  `confctl inputs channel set --commit`. The generated commit changes only
  `flake.lock`; later aitherdev commits own their configuration changes.
- `PERSISTED_STATE_FIELDS` is the single authoritative migration-state field
  declaration. Validation and recursive maximum-size projection consume it,
  and a regression proves exhaustive projected-field coverage.
- The organization flake exports only `mkPackage`; the raw constructor that
  can expose the destructive migration helper is no longer public.
- Forward, reverse and recovery moves durably synchronize both distinct source
  and destination parent directories before advancing the journal. Fault
  injection covers failures and retries on both paths.
- Authority preflight now validates the complete schema-1 identity: exact
  fields, state, slug, workspace root, socket/session/tmux identity, Codex
  triple, client version, file and directory modes and the 64 KiB limit. Tests
  cover malformed, incomplete, mismatched and trailing input. The organization
  package asserts generic authority policy version 1 so policy evolution cannot
  silently weaken this boundary.
- The runbook builds both generations first, quiesces sessions and stops the
  old non-tmux services before installing the compatibility generation, then
  stops any compatibility services that activation restarts. No reconnect or
  lifecycle command is allowed during the narrow bridge window.
- Host-root ancestors must be owned by the current effective user and must not
  be group- or world-writable before any journal or move mutation. A regression
  proves an unsafe target root leaves no migration state.
- Tracking now distinguishes earlier live rehearsals from the not-yet-started
  schema-4/final cutover.

Scope v33 also advised that the deployment checker manually traverses the
current direct lock topology and would reject `follows`. This is accepted by
design: both deployment consumers must expose direct immutable GitHub refs, and
a topology change must fail the deployment gate until the proof is deliberately
updated. The 135 retained predecessor commits and their historical add/delete
cycles are also intentionally retained for source provenance; only the current
initiative tail defines the new ownership and migration boundary.

## Compatibility and deployment assumptions

This is an intentional quiesced namespace cutover. Mixed old/new processes are
unsupported. The migration preserves exact path identities, bytes, metadata,
profile generations, tmux session/window identities, authorities, manifests,
credentials and TLS material; partial durable operations are resumable. The
old compatibility generation remains available until live acceptance passes.

No schema-4 migration journal has been deployed, so no journal upgrader is
required. Rollback is permitted only while the journaled workspace, tmux and
host inventories remain frozen. Reverse migration requires both locked,
read-only scope preflights before either scope mutates.

The user authorized aitherdev deployment, transient Codex-session restarts and
resetting development cluster state. Default-branch integration remains a
separate authorization boundary. Configuration deployment must use its feature
worktree. The registered shared workspace root still requires an explicitly
authorized fast-forward before the final alias-free package can become its
authoritative policy and metadata.
