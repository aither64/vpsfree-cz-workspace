I1 — Important, general/risk: preserve ordinary v1 unlimited /proc/meminfo.
Linux fs/proc/meminfo.c:83-87 at 86d54e7. The restored first condition includes memsw == PAGE_COUNTER_MAX and sets SwapTotal/SwapFree to zero; the immediately following unlimited else-if is consequently unreachable. A memory-limited cgroup-v1 container with unlimited memsw loses host swap capacity even with no proactive activity. The original product explicitly handled this unlimited case inside its first condition. Existing unchanged OS tests/suite/kernel/vpsadminos/memory-view.nix:203-218 require host SwapTotal/SwapFree in unlimited mode. Narrow correction: distinguish zero/no-swap from unlimited, retain host capacity, derive v1 swap-only usage as max(0, memsw_usage - memusage), and bound free capacity. Making the old else-if reachable without fixing its combined-memory usage subtraction is insufficient.

I2 — Important, general/risk: compute finite v1 meminfo free swap from the container capacity.
Linux fs/proc/meminfo.c:88-90 at 86d54e7. Restored code subtracts usage from i.totalswap before assigning memsw - totalram. At that subtraction i.totalswap still holds si_swapinfo's HOST capacity. An idle container with 128 MiB swap on a 1 GiB swap host therefore reports SwapTotal=128 MiB but SwapFree≈1 GiB. The old product assigned container capacity first and avoided this without requiring proactive charges. The same unchanged test expectations at memory-view.nix:203-218 expose the mismatch. Narrow correction: establish the container's ordinary swap capacity before deriving its free value.

I3 — Important, general/risk: retain ordinary finite-v2 free-space bounds.
Linux kernel/sys.c:2902-2904 and fs/proc/meminfo.c:98-100 at 86d54e7. The removal restores unsigned capacity - usage without the old product's zero bound. For example, 128 MiB used after reducing max to 64 MiB produces wrapped, enormous freeswap/SwapFree. This ordinary state needs no experimental charges. Narrow correction: preserve bounded zero free-space reporting in the affected finite-v2 branches. This is a concrete current-contract defect, not a demand for generalized saturation infrastructure or additional tests.
