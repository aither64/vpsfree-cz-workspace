docs/session-archive-recovery.md complete new section:

A failed direct creation can block package selection while the selected
executor cannot finish its deletion. After authorizing deletion of that exact
session, use the reviewed candidate's public recovery entry:

```sh
/path/to/candidate/bin/workspace-host recover-failed-creation-delete \
  --source /path/to/exact/source --workspace NAME --session SLUG \
  --request-id UUID
```

The command builds the supplied source and requires its output to be the exact
unselected candidate. It binds the selected predecessor profile token and native
executable, validates the native protocol, and holds transition exclusion while
ordinary deletion runs. It preserves the usual confirmation, resource ownership
checks and lifecycle journals. It does not select the candidate or restart services.
The runtime contracts must match exactly except that the candidate may add
`turnRetrySessionPolicy: 1` to a predecessor without that field. Both may also
already declare `1`. Other contract differences refuse recovery.

Admission requires the exact failed new-session request, direct team snapshot,
retained root and roster. The creating manifest must explicitly record both
`initial_goal_attempted: false` and `initial_goal_sent: false`. A matching
interrupted terminal-start journal belongs to this creation only when its slug
and tmux identity match the creating CLI journal and retained runtime identity.
Other start, fork or lifecycle conflicts remain blockers.

The ordinary deletion owner validates this same context under its existing
locks. After preflight and root quiescence, it durably records `thread_retiring`
and atomically moves the unchanged start journal to private recovery as
`start.json`. It then performs normal member and root retirement. Unknown
member starts retain their project and attempted-start provenance in the
preserved roster; this operation does not prove native absence or delete their
projects. Private recovery retains the start, creation, team and tracking records.

After interruption, repeat the same command with the same source, session and
request ID. It validates the original removal operation and private recovery
when tracking has moved. Missing or conflicting provenance refuses recovery.
Completed removal evidence makes an exact replay a no-op while the failed
receipt remains available. A missing target alone never proves completion.

After the command returns and releases transition exclusion, reconcile the
original request through the selected portal's ordinary
`GET /api/session-creations/UUID`. This status operation can retire its failed
creation receipt after proving completed deletion. It must not invoke creation
retry or start another session. If that proof fails, retain the receipt and
recovery records. Then use the normal forward package switch; its unfinished
operation and capability checks still apply. A ready replacement is unaffected.
