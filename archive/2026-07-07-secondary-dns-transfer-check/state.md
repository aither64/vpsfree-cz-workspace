## Results

- `parse_transfer_completed` matches:
  `transfer of '<zone>/IN' from <addr>#53: Transfer completed: ... serial <n>`
  and returns a `status: success` event except for empty completion summaries
  with `0 messages`, `0 records`, `0 bytes`, and `serial 0`.
- The observed timeout sequence now parses as:
  - `failed to connect: timed out` -> failed timeout
  - `Transfer status: timed out` -> failed timeout
  - `Transfer completed: 0 messages, 0 records, 0 bytes, ... (serial 0)` ->
    ignored
- `parse_transfer_status` and `parse_transfer_failed` correctly produce failed
  timeout events for the earlier lines in the ns3 sequence.
- Before the fix, each journal entry had a unique cursor, so the bogus success
  event was deduplicated separately and then became the latest transfer state
  when it had the same or later timestamp than the failure rows.
- Implemented fix:
  - parse message/record/byte counters and serial in `parse_transfer_completed`;
  - return `nil` when BIND reports an empty completion summary with
    `0 messages`, `0 records`, `0 bytes`, and `serial 0`;
  - keep non-empty completion summaries as success events, including a
    theoretical successful zone whose SOA serial is `0`;
  - add a supervisor-side defensive drop for the same raw BIND pattern so
    updating the central API protects against older nodectld instances during a
    rolling deployment.
- Existing bogus rows can be detected safely by the same raw BIND fingerprint:
  `status = 0`, `serial = 0`, `message = 'Transfer completed successfully'`,
  raw message contains `Transfer completed: 0 messages, 0 records, 0 bytes,`
  and raw message contains `(serial 0)`. Avoid deleting all success rows with
  serial `0`, because a real SOA serial `0` is theoretically possible.
- Migration behavior covered:
  - referenced bogus latest success row is deleted and latest state is restored
    to the previous failed timeout log;
  - latest state is cleared when only bogus rows remain;
  - non-empty successful transfer with serial `0` is preserved.
