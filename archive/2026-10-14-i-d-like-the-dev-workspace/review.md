## Important findings

1. A retained page acknowledges and suppresses attention for a replacement session. General/risk lanes. portal/internal/web/static/session-attention.js:56-67 replaces snapshot whenever the API identity changes, then immediately calls acknowledge and presence. It never binds that identity to the originally rendered document/root. A visible, focused old page therefore writes the replacement incarnation's event into seen and confirms it to the sender, even though its conversation belongs to the old root. Settings subsequently also use the replacement identity. The server returning rootThread does not help because the controller ignores it. I reproduced this with the actual module in a read-only Node VM: changing only the API identity/root while preserving document.body.dataset.rootThreadId caused the replacement event to be marked seen and its identity to be sent to presence. Bind the controller to the rendered observation identity; on mismatch stop acknowledgements/presence/settings and require reload. Cover retained-page slug reuse with the same root but replaced directory as well as a changed root.

2. Observer downtime silently erases an unread completion. General/risk lanes. portal/internal/web/attention.go:64-80 treats any gap over 90 seconds as a fresh baseline and clears b.Event. For an already committed, unread done event, restarting after two minutes and freshly observing the same completed lead turn and idle team destroys the title marker. Neither a visit nor authoritative supersession occurred. The existing TTL tests keep observations continuous, and the warmup test covers only a three-second gap. Preserve a previously committed current event when its exact identity/turn/request is still relevant, while independently preventing replay of completions first discovered after a gap. Add a persisted-event restart test beyond 90 seconds and both push TTLs.

3. A full outbox drops replacement events instead of coalescing them. General/architecture lanes. portal/internal/web/notifications.go:109-129 checks len(state.Outbox) >= 512 before assigning an existing browser/session key. At the supported 512-entry limit, a new input replacing a pending completion cannot be inserted. The later cleanup deletes the old now-irrelevant delivery, but reduceAttention has already consumed the emission; later reconciliations will not enqueue the new event. This loses all affected recipients even though replacement requires no extra capacity. Expired entries are also removed only after admission. Prune irrelevant/expired work before admission and allow overwriting existing keys at capacity. Test a full outbox with an existing browser/session delivery and a new higher-priority event. Source/predicate inspection confirms this failure; no Go build or integration test was launched.

4. The dependency commit's vendorHash belongs to the later imported source tree. General/history lane. Commit 0bddd694 changes nix/workspace-portal.nix:227 to the hash demonstrated by vendor-hash-final.log for a7000a2, but introduces no webpush-go import. buildGoModule's ordinary go mod vendor operation includes packages used by source imports, so its dependency-only tree does not produce the same closure as the feature tree containing notifications*.go. A cached final fixed-output path can conceal this intermediate-commit mismatch. Give each commit the hash for its own source closure, or place the inseparable dependency/import/vendorHash change together with a documented split rationale. The packet verifies only the final hash; I did not build the intermediate tree in this read-only review.

## Advisory findings

5. Incomplete registration cannot be disabled when the local subscription exists but its server ID is absent. General/risk lanes. portal/internal/web/static/browser-notifications.js:19-31 disables Disable based only on registered/registrationId. If subscribe succeeds but /register's response is lost, the subscription survives while registrationId is empty. The UI reports Disabled on this browser and offers no Disable action; a server that accepted the lost response may still deliver. The same control problem blocks the prescribed disable/re-enable recovery for an old VAPID-key subscription if localStorage no longer contains its ID. I reproduced the unavailable Disable control with the actual module and a rejected registration request. Reflect the local subscription as an incomplete state and allow explicit unsubscribe/removal recovery; do not require the user to enable again merely to disable.

6. Worker member-route validation is narrower than the supported roster contract. Architecture/general lanes. portal/internal/web/static/notification-worker.js:8-9 accepts member=[a-z]+[0-9]+, while portal/internal/teamruntime/runtime.go:36,489 supports roles containing digits. A valid address such as gpt6reviewer0 is rejected, producing only Workspace update with an index route instead of the member input notification. Reproduced by invoking the actual worker push handler. Use the supported bounded alphanumeric address grammar and add a representative case.

The mutex/body-reading concern examined during review is not reported as a demonstrated remote exploit: the selected nginx path buffers request bodies before forwarding, and the application listener is a private Unix socket. No local-operator-hardening expansion is requested.
