# Creation contract and workflow design

The generic runtime owns all functional changes. Add optional provider validation
to agentteams.DecodeCreationJournal using codexproviders.ValidID without consulting
mutable discovery. Preserve exact known-field/state checks, duplicate rejection
and all existing schema rules. Keep persistence formats unchanged.

Extend the Ruby-to-Go boundary test through a journal emitted by real Ruby
initialization, then decode/prove completion through production Go paths. Add a
packaged NixOS VM check patterned on session-archive-lifecycle: private Git origins,
installed package/user services, Chromium and stock native daemon. A loopback
Responses server supplies model catalogs, deterministic naming and sentinel
assistant/plan output. Creation forms and HTTP handlers, CLI, journal readers,
root/team creation, provider routing and receipt proofs remain unchanged.

The browser driver asserts durable progress, canonical navigation, accessible
transcript and one successful follow-up. Count exact initial user-turn markers
and actual root/member IDs through native reads. A shared scenario driver keeps
a bounded matrix instead of a full Cartesian product. Cover the named settings
across representative scenarios, plus fork/plan destinations and recovery at
before-native/after-send boundaries using test-only external barriers. Never
install product test hooks or replace ready proofs with fabricated JSON.

Faults and restart tests retain request IDs and frozen settings; retries must
finish the original destination once. Ready state must agree between preparation,
receipt, manifest and creation journal, and remain accessible after portal restart.
Delete the owned failed request through normal lifecycle tools and confirm stale
replay cannot create a replacement. Failure renderer selection/copy remains covered.

All checks run in declared Nix environments. Quick contracts precede mandatory
review. Long VM/package/CI checks run under fresh installed Luna/low watchers.
No schema migrations. Old/new component deployment: matching host contract then
profile using coordinated prepared jobs. Preserve stock native binary and user
provider defaults. Retain reservation for live whole-flow acceptance and release
only after final exact default integrations. Rollback requires a package whose
Go reader accepts the already supported provider field.
