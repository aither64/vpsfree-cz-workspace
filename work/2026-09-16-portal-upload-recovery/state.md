## Behavior and compatibility

Remove previously retried creation for every no-ID draft, so a rejected filename
could never clear. Browser persistence also lost its error. Creation outcomes and
errors now survive reload; known local-only selections clear without a request.
Legacy or uncertain creates reconcile the same scoped client identity before
deletion. A DELETE 404 requires an authorized listing confirming absence, because
the runtime can also use 404 for temporary scope restrictions. Other failures
remain visible and retryable. Persistence failures keep the card and prevent
submission of deleted or uncertain attachments.

Filenames remain metadata. Storage still uses UUID directories and a restricted
extension, with text-node rendering, JSON serialization and MIME header formatting.
Existing client identities are resolved before stricter new-upload admission, so
old C1-containing catalog names remain recoverable. Catalogs, paths, quotas,
submission contracts, Codex version/protocol and host state schemas are unchanged.
The nested browser cache chain advances conversation.js v8 to v9 and uploads.js
v2 to v3. Rollback retains bytes and acknowledged drafts but restores older UI
and admission limitations.
