## Behavior and boundaries

`last_confirmed_at` is nullable and internal. Complete non-transitioning reports
must match the baseline boot, release and effective patch IDs. Current and
supplied previous reports can advance confirmation under the node lock.
`update_columns` preserves updated_at, original bounds, snapshots and public
event revision. Removal/release lower bounds use retained confirmation;
application-specific complete preceding non-effective reports remain supported.
No protocol/public API field/WebUI wording or layout changes are intended.

Repair requires one eligible node, defaults to dry-run, and accepts only unset/0
or 1 for APPLY. It freezes candidate IDs, batches processing and evidence lookup,
uses immutable snapshots referenced by retained events (including internal
ones), and compares through the same StableState helper. It tightens strictly
inside the interval, never seeds migration-time values, and prints reasons and
totals. Before writes it re-reads target, predecessor and selected evidence under
the node lock; a changed proposal is skipped. Writes update updated_at normally.
Raw logs, mutable current snapshots and uname-only samples are excluded.
Insufficient retained evidence remains an accepted conservative outcome.

The helper belongs to vpsAdmin API KernelEvidence. Consumers are the supervisor's
existing recorder path and the new operator repair task. Existing API resources
and WebUI consume existing event bounds and revision hashes without new fields.
The configuration pin changes packages used by API/supervisor and other channel
consumers, with no node or vpsAdminOS update.
