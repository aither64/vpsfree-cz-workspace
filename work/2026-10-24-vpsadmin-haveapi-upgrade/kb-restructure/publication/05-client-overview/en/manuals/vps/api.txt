====== API ======

Our API is running at https://api.vpsfree.cz. The API can be used to perform
any action that you can do in the web interface. In fact, the web interface
running at https://vpsadmin.vpsfree.cz uses the API and calls it for every
action.

===== API Documentation =====
The API documentation, i.e. a list of objects, possible actions as well as input and output
parameters can be found at https://api.vpsfree.cz/.

Even without logging in, you can see a list of all objects, i.e. even those that only
administrators can work with. On the top right, you can log in using the same credentials
as in vpsAdmin. Afterwards, you will only see the objects, actions and parameters that
the user who is currently logged in can work with.

===== Working with the API =====
The API uses the [[https://github.com/vpsfreecz/haveapi|HaveAPI]] framework.
Its [[https://github.com/vpsfreecz/haveapi#what-is-a-self-describing-api|self-description]]
lists the available resources, actions and parameters.

The following clients are available:

  * [[#installing_vpsfree-client|vpsfreectl CLI]] and [[#ruby_client|Ruby library]]: the main client, provided by ''vpsfree-client''.
  * [[#php_client|PHP]]
  * [[#python_client|Python]]
  * [[#haveapi_client_for_javascript_and_typescript|Generic HaveAPI client for JavaScript and TypeScript]]
  * [[#go_client|Go]]
  * [[#vpsadmin_typescript_client|vpsAdmin TypeScript client]]
  * [[#rust_client|Rust]]

The API is [[wp>Representational state transfer|RESTful]], so any REST client
can be used for simple actions. A description of the custom data transfer protocol
that HaveAPI clients abstract can be found in
[[https://api.vpsfree.cz/doc/protocol.md|the documentation]].

===== Authentication=====
There are two authentication methods:

  * [[#http_basic|HTTP Basic]]
  * [[#tokens|Using tokens]]

Example usage in different programming languages can be found in [[https://api.vpsfree.cz/v6.0/#auth|API documentation]].

==== HTTP Basic ====
 The name and password must be sent along with every API request in HTTP header //Authorization//.
This is a good choice for one-off actions. However, if you need to call the API repeatedly or
automatically, storing the password on the disk or entering it constantly is not a good idea.
HTTP Basic cannot be used if two-factor authentication is enabled on your account.

==== Tokens ====
The client first requests a token using your credentials and optionally also TOTP.
As soon as the client receives the token, the credentials can be forgotten and the token
is used for authentication.

There can be several types of tokens with different lifetimes:

  * //fixed// - token validity is fixed
  * //renewable_manual// - token validity can be manually extended
  * //renewable_auto// - token validity is extended after every request
  * //permanent// - the token is valid permanently, or until it is deleted

The type of token and time period by which its validity is extended is chosen
by the client.

===== Scopes =====
Authentication tokens can be restricted to selected actions. Each action has its own scope,
you can find the available scopes in the documentation. You can configure scopes when you're
requesting a new authentication token.

Example scopes:

  * ''all'' allow access to all actions, this is used by the web interface and it is the default scope
  *  an empty scope will allow access only to ''user#current'', which gives information about the current user; this is used for logins from Discourse and KB
  * ''vps#show'' allow access to action show on vps resource
  * ''vps#show:vps_id=123'' allow access to action show on a specific VPS
  * ''vps#*'' allow all actions on vps resource
  * ''vps#*:vps_id=123'' all actions on vps resource, but only with VPS ID 123
  * ''{vps,dataset}#{index,show}'' list and show info about VPS and datasets

Scopes can contain globs for resource and action names. Action name is separated from resource name by a hash (''#''). Optional object IDs are separated from action name by a colon ('':'') and cannot contain globs. You can find a list of available scopes and their parameters in the [[https://api.vpsfree.cz/|documentation]]. Each token can have multiple scopes separated by spaces. At least one scope must match the called action in order for access to be granted.

===== Installing vpsfree-client =====
The main client is [[https://github.com/vpsfreecz/vpsfree-client|vpsfree-client]]
for Ruby. It includes the ''vpsfreectl'' command-line tool and a library for Ruby
scripts, both installed from the same package.
In order for it to work properly, you need Ruby >= 2.7, Ruby header files and ncurses (mostly packages with the ''-dev'' or ''-devel'' suffix).

<code bash>
gem install vpsfree-client
</code>

Platform-specific instructions:

  * [[manuals:vps:api:macos|macOS]]
  * [[manuals:vps:api:windows|Windows]]

After the installation, ''vpsfreectl'' should be available in ''$PATH''. If not,
this can be fixed easily:

<code>
$ gem env | grep "EXECUTABLE DIRECTORY"
</code>

This command will display the location of all executables installed using
''gem''. All you need to do is add that folder to ''$PATH'', e.g.:

<code>
$ PATH="$PATH:/home/user/.gem/ruby/3.0.0/bin"
</code>

==== Authentication ====
=== HTTP Basic ===
You can either pass the username and password using the ''%%--username%%'' and ''%%--password%%'' parameters or
you can skip the parameters and the program will prompt the user to input the credentials.
<code>
$ vpsfreectl --auth basic user current
</code>

=== Tokens ===
Authentication using tokens creates a few new options:

<code>
$ vpsfreectl --auth token --help
    ...
    -a, --auth METHOD                Authentication method
    -s, --save                       Save credentials to config file for later
        --user USER                  User name
        --password PASSWORD          Password
        --scope [SCOPE]              Scope
        --token TOKEN                Token
        --token-lifetime LIFETIME    Token lifetime, defaults to renewable_auto
        --token-interval SECONDS     How long will token be valid in seconds
        --new-token                  Request new token
        --token-via VIA              Send token as a query parameter or in HTTP header (query_param, header)
    ...
</code>

Again, you don’t have to send the username and password as parameters, the program will request them.

One-time token:
<code>
$ vpsfreectl --auth token user current
</code>
After finishing, the token is forgotten and next time you will need to request a new one. A token for
a use like this makes no sense.

Saving the token:
<code>
$ vpsfreectl --auth token --save user current
</code>

The token is saved in the  ''~/.haveapi-client.yml'' file and automatically loaded
upon the next startup.
<code>
$ vpsfreectl user current
</code>

However, a token like this expires within 20 minutes and it is necessary to request a new one. It is possible to
create a token with a longer validity right away:

<code>
$ vpsfreectl --auth token --save --token-interval $((24*60*60)) user current # 1 day
</code>

Or a token with a permanent lifetime straight away:
<code>
$ vpsfreectl --auth token --save --token-lifetime permanent user current
</code>

<note warning>
Be careful if you’re using tokens with an unlimited validity since anybody with
access to ''~/.haveapi-client.yml'' can access and use the token.
</note>

Specify a scope:

<code>
$ vpsfreectl --auth token --scope 'vps#*:vps_id=123' --save vps show 123
</code>

The command above will ask for an authentication token that will only be allowed to call actions on the vps resource and only on VPS with ID 123.

==== Actions and Parameters ====
Objects and actions have the same names as they do in the documentation – they’re just written in lowercase letters and
underscores are used instead of spaces. Every action has its input and output parameters.
These can be displayed using the ''%%--help%%'' parameter if you provide the names of both the object and the action.

<code>
$ vpsfreectl vps list --help

You can filter VPSs by server, location, environment, distro, state
and limit the number of displayed items or pages.

Action parameters are separated from client parameters by two dashes ''%%--%%''.
The following command displays the first three VPSs:

<code>
$ vpsfreectl vps list -- --limit 3
</code>

If, for example, you want to filter by location, you first have to display a list of locations:

<code>
$ vpsfreectl location list
 ID  Label      
  3  Praha      
  4  Brno       
  5  Playground
</code>

Now let’s display the VPSs found in the “Praha” (Prague) location:

<code>
$ vpsfreectl vps list -- --location 3
</code>

==== Output Formatting ====
The output can be either formatted into columns or rows. Under default settings,
columns are used to display a group of objects and lines are used for a single object. You can choose
the format using the ''-c'' option, ''%%--columns%%'' for columns and ''%%--rows%%''
for rows.

An example of the output formatted in columns (in this case the ''%%--columns%%'' option is
unnecessary – it will be chosen automatically since the output contains several objects):
<code>
$ vpsfreectl vps list --columns
 ID  Label      
  3  Praha      
  4  Brno       
  5  Playground
</code>

An example of the output formatted into rows:
<code>
$ vpsfreectl location list --rows
    ID:  3
 Label:  Praha

    ID:  4
 Label:  Brno

    ID:  5
 Label:  Playground
</code>

When used in scripts, the column formatting could be problematic due to the header
with parameter names. You can disable it using the ''-H'', ''%%--no-header%%'' option
so that it won’t be displayed.

==== Choosing the Parameters to Display ====
The  ''-o'', ''%%--output%%'' option is used to set what output parameters of the action
and in which order they will be displayed. Parameter names are separated by a comma.

<code>
$ vpsfreectl vps list -o id,hostname,node,os_template
      VPS id:  4710
    Hostname:  vps
        Node:  node7.prg (#108)
 OS template:  CentOS 7 (#43)
</code>

==== Date and Time Format ====
The client includes several options that are used to choose the date and time format
if an action returns a parameter of the type ''Datetime''.

  * ''%%--utc%%''
  * ''%%--localtime%%''
  * ''%%--timestamp%%''
  * ''%%--date-format FORMAT%%'' - format according to [[http://ruby-doc.org/core-2.3.0/Time.html#method-i-strftime|Time#strftime]]

===== Updates =====

In order to make use of new features, the client needs to be updated from time to time. This is done
using the following command:

<code>
$ gem update vpsfree-client
</code>

Then you can remove the old version:

<code>
$ gem cleanup vpsfree-client
</code>

This command only removes the old versions of the ''vpsfree-client'' gem, but its
dependencies remain. In order to remove all old gems, use the following command:

<code>
$ gem cleanup -n  # prints which gems would be deleted
$ gem cleanup  # deletes the gems
</code>

===== Ruby client =====

Use the library from the same ''vpsfree-client'' package in your own scripts.
With an existing token in ''VPSADMIN_TOKEN'', you can list VPSes as follows:

<code ruby>
require 'vpsfree/client'

api = VpsFree::Client.new
api.authenticate(:token, token: ENV.fetch('VPSADMIN_TOKEN'))

api.vps.list.each do |vps|
  puts "#{vps.id}: #{vps.hostname}"
end
</code>

See the [[https://github.com/vpsfreecz/vpsfree-client#client-library|client README]]
for more library examples.

==== Usage Examples ====
The following scripts demonstrate ways you can use the API. These scripts can be
run from anywhere – manually, from cron, etc.

<note>
Although these examples are still valid, the CLI client already contains
[[manuals:vps:datasets#downloading_backups|commands]] which make downloading backups
even easier.
</note>

=== Daily Downloads of VPS Backups ===
<code>
#!/usr/bin/env ruby
# Downloading the last (most recent) backup of all VPSs.
require 'vpsfree/client'

api = VpsFree::Client.new
api.authenticate(:token, token: 'PUT YOUR TOKEN HERE')

api.dataset.list(role: :hypervisor).each do |ds|
  last_snapshot = ds.snapshot.list.last

  # This action may take up to several hours
  dl = api.snapshot_download.create(snapshot: last_snapshot.id)

  unless dl.api_response.ok?
    warn "#{ds.name}@#{last_snapshot.created_at}: #{dl.api_response.message}"
    next
  end
  
  # The file is ready for download
  puts "Downloading #{id} to #{dl.file_name} (#{dl.size / 1024} GB)"
  `wget #{dl.url}`

  # Finally, delete the file from the server
  dl.delete
end

puts "Done"
</code>

=== Daily NAS Backups with a Weekly History ===
<code>
#!/usr/bin/env ruby
# Daily NAS snapshotting with a 7-day history
require 'vpsfree/client'

api = VpsFree::Client.new
api.authenticate(:token, token: 'PUT YOUR TOKEN HERE')

api.dataset.list(role: :primary).each do |ds|
  # Creating a new snapshot
  ds.snapshot.create

  # Deleting older snapshots
  t = Time.now - 7 * 24 * 60 * 60
  snapshots = ds.snapshot.list(meta: {count: true})
  deleted = 0
  
  snapshots.each do |snap|
    # Keep at least 7 snapshots
    break if snapshots.total_count - deleted < 7
    
    # Deleting redundant snapshots older than 7 days
    if snap.created_at < t
      puts "Delete #{ds.name}@#{snap.created_at}"
      snap.delete
      deleted += 1
    end
  end
end
</code>

===== Other clients =====

The generic HaveAPI clients for PHP, Python, JavaScript and TypeScript download
the available resources, actions and parameters from the server. The vpsAdmin
clients for Go, Rust and TypeScript provide methods and types for a specific API
version. Each client's README covers installation, authentication and further examples.

==== PHP client ====

Install the [[https://github.com/vpsfreecz/haveapi/tree/master/clients/php|HaveAPI PHP client]]
using Composer:

<code bash>
composer require haveapi/client
</code>

After loading the autoloader, use an existing token from ''VPSADMIN_TOKEN'':

<code php>
<?php
require __DIR__ . '/vendor/autoload.php';

$token = getenv('VPSADMIN_TOKEN');
if (!$token) {
    throw new RuntimeException('Set VPSADMIN_TOKEN');
}

$api = new \HaveAPI\Client('https://api.vpsfree.cz', '7.0');
$api->authenticate('token', ['token' => $token]);

foreach ($api->vps->list() as $vps) {
    echo $vps->id . ': ' . $vps->hostname . PHP_EOL;
}
</code>

The client exposes resources and actions as properties and methods. See the
[[https://github.com/vpsfreecz/haveapi/tree/master/clients/php#usage|client README]]
for action parameters, responses and error handling.

==== Python client ====

Install the [[https://pypi.org/project/haveapi-client/|haveapi-client]] package using pip.
See the package page for Python requirements.

<code bash>
python -m pip install haveapi-client
</code>

Import ''Client'' for synchronous calls or ''AsyncClient'' for asynchronous
calls from ''haveapi_client''. Both support ''TokenAuth'', ''BasicAuth'' and
''OAuth2Auth''. For example, with an existing token in ''VPSADMIN_TOKEN'':

<code python>
import os
from haveapi_client import Client, TokenAuth

with Client("https://api.vpsfree.cz", version="7.0",
            auth=TokenAuth(os.environ["VPSADMIN_TOKEN"])) as api:
    result = api.vps.list.call(params={"limit": 10})
    for vps in result.data:
        print(vps["id"], vps["hostname"])
</code>

With ''AsyncClient'', use ''async with'' and await the action call. See the
[[https://github.com/vpsfreecz/haveapi/tree/master/clients/python|client README]]
for authentication and asynchronous examples.

==== HaveAPI client for JavaScript and TypeScript ====

Both languages use the same npm package, which includes TypeScript declarations:

<code bash>
npm install haveapi-client
</code>

''AsyncClient'' provides a Promise-based interface. This Node.js example uses
an existing token in ''VPSADMIN_TOKEN'':

<code typescript>
import { AsyncClient } from "haveapi-client";

async function main() {
  const token = process.env.VPSADMIN_TOKEN;
  if (!token) throw new Error("Set VPSADMIN_TOKEN");
  const api = new AsyncClient("https://api.vpsfree.cz", { version: "7.0" });
  await api.authenticate("token", { token });
  const result = await api.resource("vps").action("list")({
    params: { limit: 10 },
  });
  console.log(result.value);
}

main().catch(console.error);
</code>

The package also provides the callback-based ''Client'' and ''CallbackClient''.
See the [[https://github.com/vpsfreecz/haveapi/tree/master/clients/js|client README]]
for browser usage and typed result handling.

==== Go client ====

The [[https://github.com/vpsfreecz/vpsadmin-go-client|vpsAdmin Go client]] provides
types for API 7.0 resources, actions and parameters. Add it to your Go module:

<code bash>
go get github.com/vpsfreecz/vpsadmin-go-client/client
</code>

Create the client with ''%%client.New("https://api.vpsfree.cz")%%'' and pass an existing
token to ''SetExistingTokenAuth''. The base URL does not include ''/v7.0/'' because
the action paths already contain the version. See the
[[https://github.com/vpsfreecz/vpsadmin-go-client#usage|client README]] for a complete
VPS listing example and other action calls.

==== vpsAdmin TypeScript client ====

The [[https://github.com/vpsfreecz/vpsadmin-typescript-client|vpsAdmin TypeScript client]]
provides methods for API 7.0 resources and actions, with types for their parameters
and results. Your editor can use these types to suggest resource names, actions
and parameters as you write code.
The generic ''haveapi-client'' discovers the API at runtime and provides the
Promise and callback interfaces described above.

Install the client package. npm installs a compatible ''haveapi-client''
according to its declared dependency:

<code bash>
npm install vpsadmin-typescript-client
</code>

The [[https://github.com/vpsfreecz/vpsadmin-typescript-client#readme|client README]]
describes ''createVpsAdminClient'', authentication and action calls.

==== Rust client ====

The [[https://github.com/vpsfreecz/vpsadmin-rust-client|vpsAdmin Rust client]]
supports API 7.0. See the
[[https://github.com/vpsfreecz/vpsadmin-rust-client#readme|client README]] for Rust requirements.
Add the [[https://crates.io/crates/vpsadmin-client|vpsadmin-client]] crate to your project:

<code bash>
cargo add vpsadmin-client
</code>

Use ''vpsadmin_client::Client'' for asynchronous calls. For synchronous calls,
enable the ''blocking'' feature:

<code bash>
cargo add vpsadmin-client --features blocking
</code>

Then use ''vpsadmin_client::blocking::Client''. The
[[https://github.com/vpsfreecz/vpsadmin-rust-client#readme|client README]]
contains token authentication and action examples.
