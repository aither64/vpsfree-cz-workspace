# Session-scoped provider transitions

## Scope and ownership

The lead owns design and application edits. The initiative has no retained native
roster. A mandatory standalone reviewer and fresh verification utilities remain
independent. Scope is dev-workspace plus the additive codex-web lifecycle/settings
interface already implemented. No default-branch integration or live rollout is
authorized. Keep the working workspace usable while developing on isolated state.

Each session explicitly selects a provider or inherits the workspace default.
Changing the default updates inherited sessions and preserves explicit selections.
Creation freezes its optional provider into the accepted incarnation and exact
root. Reusing a deleted slug cannot acquire a former selection. Preserve native
histories, thread IDs, queued submissions and delivery identities, current goals,
model/effort, policies, instructions, member addresses and terminal environments.

The user explicitly rejected a downstream Codex patch and its repeated build
cost, then accepted stopping temporary subagents during a switch. Completion
requires the lead and every retained member to use the target. Idle retained
members remain in scope. Existing temporary agents may stop and their delegated
work may need reassignment; saved histories remain. New agents inherit the
switched parent. Do not preserve the abandoned in-place implementation.

## Stock native transition

Use the selected upstream native binary and its supported thread/archive,
thread/unarchive and thread/resume operations. Resume cannot change routing on
an already loaded thread, so close the selected retained runtimes, reopen the
same histories with target provider/settings, verify them, and send correlated
continuations for interrupted ordinary work. Native goal and queue persistence
own their current state; never replay goal activation. Native tree teardown
stops temporary descendants. Do not inventory, migrate, resume or directly
modify temporary children. Retained leads and members are independent roots.

Preserve settings and exact thread identity through existing cold-resume
validation. Unsupported cold permissions refuse before closure with a visible
reason. This process follows ordinary native interruption semantics; running
tools/questions can be canceled and a continuation must inspect prior results
before repeating actions. It does not add a native hot-update capability.
Shared services and unrelated sessions remain alive.

The downstream patch was never deployed/released/externally consumed. Native
builds 1/2 failed; build 3 was deliberately canceled after the user rejected the
patch. Remove the native patch, protocol proof, native tests and Nix override
from the final branch, keeping the selected Codex package unchanged. Earlier
review findings tied to that implementation are resolved by its removal, not by
claiming it worked. Keep review evidence in session records.

## Scoped admission, progress and recovery

Accept requests durably before inventory/model checks. Publish scope, stages,
timestamps, completed/total threads and safe reasons immediately. Acquire only
affected session runtime authorities and a shared package-generation lock.
Lifecycle conflicts and changed root identities refuse. Quiesce and restore only
affected terminal clients. Do not wait for unrelated native threads, goals,
submission receipts, VM runners or utility descendants. Use metadata/turn headers
rather than full transcripts for provider decisions.

Inventory exact retained leads and ready roster members. Preflight target
models/authentication and all cold-resume settings before mutation. Journal
close, reopen, verification and continuation boundaries. Recover forward to the
accepted target after a lost reply or process restart. Reopening is repeatable;
verified retained threads are not closed again. Preserve continuation IDs and
native current goal ownership. Do not report partial retained-member routing as
success or roll the workspace back silently. Terminal restoration failures
retain the selection and a durable retry notice.

Workspace-default changes freeze inherited roots under an exclusive creation
admission lock. Creators retain its shared side through root publication, so a
concurrent inherited creator cannot fall between inventory and applying. Session
switches do not acquire this workspace freeze. Generation locks fence native
mutation from package changes; unfinished provider operations fence activation.

## Catalogs, creation and compatibility

Provider-specific model-only servers serve cached destination catalogs without
loading conversations or restarting the shared daemon. Browser validation and
pickers use that provider catalog, as do CLI creation and retained team settings.
New/plan creation uses its destination; forks use the workspace default independent
of the source. Browser drafts, preparation snapshot/handoff, portal receipts and
the original CLI creation journal retain accepted provider selection/settings.
All matching readers validate those fields, including completed CLI journals.

Schema 2 introduces exact-root selections, scoped transitions and bounded receipts.
Schema 1 remains readable; unfinished deployed operations use their original
engine before accepting a new scoped request. No intermediate
scoped-state release or external consumer exists. No database migrations exist.
Older workspace packages must refuse scoped state and retained creation formats
through the advertised state/policy capabilities, including preparations/receipts
written before provider state exists. Legacy records without new fields retain
their original inspection policy. Preparation input and accepted handoff both
participate in this admission check.

No native patch, native version upgrade, storage schema change or migration
is introduced. The existing complete-package assembly remains unchanged and
uses the selected prebuilt upstream output. The genuine deployed schema-1
workspace-wide recovery engine remains supported. The abandoned native and
scoped temporary-child migration designs have no supported consumers.

The codex-web request-aware lifecycle/settings resolver remains additive. Existing
thread-only resolver users retain their behavior. Browser inputs carry only
catalog IDs and session slugs. Trusted code resolves all sockets, roots, native
IDs, endpoints and policies. Progress contains no credentials, transcript text
or private configuration. Operators are trusted host administrators; concurrent
operations, ownership mistakes, untrusted web input and interrupted recovery
remain in scope.

## Verification and documentation

Quick checks: focused Go provider tests, browser contracts and syntax/format
checks. Final independent review covers the complete consolidated branch and
changed stock-native behavior, using the same resumable reviewer. Only after
its findings are resolved run isolated native/package tests with a fresh watcher.

The exact unchanged native fixture must include a real retained roster member,
an old temporary v2 child stopped during parent closure, a new child inheriting
the target, actual per-retained-thread target HTTP requests, ordinary work,
current goals with/without queue, exact queued identity, idle state, unrelated
busy work and repeat recovery. Verify without live sockets, credentials or
inference. Reuse unchanged browser/CI evidence only where its inputs match.
No live switch, activation, merge or deployment is authorized.

Feature behavior/recovery lives in dev-workspace docs/codex-providers.md. The
native protocol and packaging contract lives in docs/codex-package.md; session
and portal guides link to them. The reusable resolver contract belongs to
codex-web README. Exact rollout plans, revisions and actual effects belong in a
separate rollout record only if rollout is later authorized.
