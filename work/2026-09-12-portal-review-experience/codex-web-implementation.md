Review architecture findings 2/3 and the typed-renderer advisory are addressed:

- `NewActivityRecorder(path)` now owns a directory, not the abandoned single
  JSON file. No migration is needed for the undeployed branch iteration.
  Each thread has independent asynchronous writes, a bounded current
  checkpoint, and a small summary file per observed turn. Directories are
  0700 and files are 0600. Native files only; no new dependency.
- Current state holds at most 128 outstanding requests and 128 turns awaiting
  compaction. Resolved requests disappear. Historical totals have no shared

  mutex. Slow or failed writes leave pending time unclassified. Sequence
  numbers preserve the newer summary across a crash before checkpoint rename.
- Per-thread history gates are cancellable. Successful pages survive a
  cancelled backfill so a later four-second read can continue. The existing
  100,000-turn read safety bound remains local to optional activity reads.
- ReadThread again requests just the recent 20 full turns. Unused public
  Transcript.Turns and ActivitySnapshot.Turns are removed; the activity JSON
  response contains only aggregates and current-turn fields. Required Client
  and optional ActivityProvider interfaces remain compatible.
- The shared JS renderer selects validated activity data instead of repeating
  Go's kind whitelist. Its exported API is unchanged.

The confirmed provider lifetime finding is addressed:

- History entries have watch and read ownership under one short mutex. Watches
  acquire ownership before their first history read. All readers, including
  metadata reads and callers queued on the per-thread gate, pin the entry.
- Last unsubscribe releases only its watch ownership; it cannot remove or
  replace the cache held by an active/queued reader.
- The last reader releases completed unwatched histories. At most eight idle
  incomplete histories retain successful pages for retry. Reacquisition pins
  the entry; adding another idle history evicts the oldest unpinned entry.
- Recorder setup errors, metadata failures, invalid identity, page errors and
  cancelled gate waits all release read ownership. No durable summary,
  deletion, retention-policy, protocol-version or dependency change was made.
- README now states the eight-entry partial-history retry contract and
  distinguishes history caches from recorder cache retirement. The owner
  applied the required English writing skill directly.

The provider portion of the Important finding in
`review-final-architecture.md` is addressed:

- ObserverOnly clients share four connected-RPC slots across normal
  metadata/history reads, resume and unsubscribe calls. Caller contexts bound
  queue waiting; the observer's ten-second RPC timeout starts after admission.
- A fixed four-worker restore pool consumes a replaceable queue bound to the
  live connection generation. Disconnect and Close cancel and clear queued

  publish stale watch notices or coverage.

  connection immediately closes. This observer-only bookkeeping avoids a race
  between the restore worker and concurrent Subscribe while retaining the
  existing rule that closed transports cannot establish coverage.
- Interactive clients keep their existing request admission and timeout
  behavior. No public option, protocol shape, request authority, dependency or
  persistent-state contract changed. The protocol corpus scanner recognizes
