# Workspace Codex contract coverage before deployment

## Symptom

`workspace-host switch` passed the sandbox package build but stopped during its
Codex compatibility preflight because an implemented `thread/list` call had no
matching request in `test/codex_protocol_contract.py`.

## Cause

The complete protocol validator needs schemas generated by the installed Codex
version, so it ran only during profile switching. Package checks did not compare
the static request-call inventory with the request corpus.

## Fix

Keep one corpus entry for every request call site and run the validator's
`--coverage-only` mode from the package check phase. The coverage-only check
needs no installed Codex schemas; profile switching still validates every
sample against the actual installed version.

## Verification

The coverage-only check passed, the complete sandboxed workspace package built,
and the packaged validator accepted the installed Codex 0.153.4 App Server
schema.
