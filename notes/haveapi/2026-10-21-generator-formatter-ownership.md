# Generator formatter ownership

A HaveAPI nixpkgs update can change rustfmt independently of an existing
client's saved generation configuration. In the Rust-generator initiative,
HaveAPI's updated shell supplied rustfmt1.10.0 while the real client retained
its own pinned1.9.0. Four temporary generator specs and a saved-client package
probe stopped at the intended exact-version guard before rendering.

Temporary fixture configs should derive the exact version from the same
selected executable as generation (`ENV.fetch('RUSTFMT', 'rustfmt')`), requiring
a successful nonempty version probe. Saved client configs retain their exact
formatter and generated bytes. Do not update expected files or relax the
production guard to accommodate a different shell.

For extracted-generator acceptance under a newer HaveAPI Ruby, retain that
Ruby and select the saved client's pinned rustfmt with the existing `RUSTFMT`
override. Keep the override scoped to that operation; generic integration
fixtures can use current HaveAPI tools. Root the restored executable until
verification ends and record both toolchain pins/versions. A changed package
README is a changed archive payload even when generator/runtime digests match.
